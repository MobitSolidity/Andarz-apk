Notation: §n = a section of the prompt · Kn = a section of this message · D-nn = a decision of the prompt (§13.1) · D-Mnn = a decision of this message (K10).

## K0 — Mission

Build ONE Android app, «اندرز» (Andarz):

- the discipline engine and trading journal exactly as the prompt specifies (gate, governor, journal, reviews, insights, constitution, encrypted backup), plus
- the features of March (the owner's price-and-news app, package ir.bazaaryar.app) as an isolated Market section: live prices for the top 200 coins, the USDT/Toman rate, Fear & Greed, starred coins, price alerts that can ring like an alarm clock, an economic-release calendar with reminders, and an opt-in background monitor.

Andarz is the host: its architecture, laws (as amended in K2), golden vectors, theme and navigation win. March supplies working behavior and code; it is read-only and is never changed.
Prices are information. They never decide anything about the trader's risk: the gate, sizing, governor and KPIs read only numbers the trader typed (D-M06).

## K4 — Architecture and network rules

    ANDARZ/
      spec/       read-only inputs, never edited
      engine/     pure Kotlin/JVM, as in the prompt; depends on nothing
      data/       Android library, as in the prompt; depends on :engine only
      market/     NEW Android library, namespace ir.andarz.market: everything from March that touches the network, prices, alerts,
                  alarms, the calendar, the foreground service and boot restore
      app/        Compose UI for the journal AND the Market screens, Hilt, navigation, adapters that connect :market to the app
      tools/      scripts (string extraction, helpers for the guards)

Dependency rules (a Gradle verification task fails the build when one is broken):
- :engine depends on nothing; :data on :engine; :market on no project module; :app on :engine, :data and :market. Nothing depends on :app, and nothing but :app depends on :market.
- Reason: a bug or a library in the network code must not be able to read the journal. :market cannot import one class from :data or :engine.

:market contains: models, MarketHttp (the only OkHttp client, internal), CoinRepository, BinanceStream, IranMarket, PriceHistory, PriceHub, MarketPrefs (its own DataStore "market"), PriceAlerts (pure evaluator plus dispatcher), AlarmRinger, ClockRing, ClockApp, AlarmActivity with its small Compose screen, LiveService, Reminders with the receivers, the calendar loader, the drawable ic_stat_market and the manifest of K8.1.

:market public surface (small on purpose; this is a sketch, refine it):

    interface MarketHost {                       // implemented in :app, installed from Application.onCreate
        val texts: MarketTexts                   // every user-visible word :market shows
        fun openIntent(context: Context, target: MarketTarget): Intent   // explicit, FLAG_IMMUTABLE deep link into MainActivity
    }
    interface MarketTexts { /* typed alert events in, strings out: :market has no Persian and no number formatting */ }
    sealed interface MarketTarget {
        data class Coin(val id: String) : MarketTarget
        data object News : MarketTarget
        data object Home : MarketTarget
    }
    object MarketModule {
        fun install(app: Application, host: MarketHost)
        val repository: MarketRepository         // StateFlows, acquire(ui), refreshNow(), extraSymbols
        val alerts: AlertsController
        val calendar: CalendarController
        // also: prefs export/import, onRestored(), appVisible/appHidden hooks
    }

Everything else is internal. Typed errors cross the boundary (NoNetwork, Timeout(service), RateLimited(service), Blocked(service), Server(service, code)); localized error strings do not. The ContentRepository must be callable from any thread and from a receiver in a cold process (lazy load, no UI), because notifications are built there.

:app contains for Market: ui/market/ (Prices, CoinSheet, MyCoins, News, Alerts), MarketFmt, Hilt view models, MarketHostImpl (texts from content, deep links), the Hilt module that exposes MarketModule's parts, the market/* navigation graph.

### Network egress (the whole app)

- Only :market's MarketHttp opens connections. HTTPS and WSS only: usesCleartextTraffic=false plus a network_security_config that forbids cleartext.
- Hosts, as constants and exactly these: api.coingecko.com, api.alternative.me, data-stream.binance.vision (WSS), api.nobitex.ir, api.wallex.ir. A new host needs a D-M entry and a change of the consent text.
- HTTP: GET only, no body, no cookies, no authorization; headers limited to Accept and a generic User-Agent "Andarz-Market/<version>". WebSocket: the only client frames are SUBSCRIBE messages whose params match ^[a-z0-9]{2,15}usdt@miniTicker$.
- Query strings are static or contain only coin ids and symbols from the market catalog. Never a value from :data or :engine, a device identifier or the user's name.
- An OkHttp interceptor enforces host, method and scheme and throws otherwise. Tests (MockWebServer or a fake Call.Factory) prove that a POST, an http:// URL and an unknown host are refused. The same constants feed the consent sheet and the About network page, so the text cannot drift from the code.
- Zero-traffic rule: with Market off (the default), or on but not demanded, the app opens no socket and issues no request. A unit test proves it.
- Consent gate: before the first request ever, a one-time sheet (mkt.consent.*) lists the hosts and says what is and is not sent; the hub starts only after "accept". The master switch (Settings → Market, and the off state of Prices and My coins) defaults to off and can be turned off at any time; off stops the hub, the service and every price alert. It gates network use only: the News calendar and its release reminders are local and keep working with the switch off, and Alerts shows its settings with a note that price alerts need Market on. Neither consent nor the switch is restored from a backup.

### K5.2 — Behavior to preserve exactly (port, do not redesign)

- Data cadence: CoinGecko top 200 every 60 s while Market is on screen and every 5 min in background-only runs, back-off 2 min on HTTP 429; Nobitex (fallback Wallex) USDT/Toman every 10 s; overview every 5 min; Binance ticks about every second, Nobitex prices when the WebSocket has not delivered for 15 s; history samples every 5 s; a quote older than 10 min is not used. In background-only runs only watch-list and rule coins are streamed.
- Alerts: windows 5 min / 15 min / 1 h / 24 h; percent threshold with a per-coin override; direction up, down or both; cooldown in minutes; scope watch-list or all; include USDT/Toman; one-shot absolute targets above and below; ring modes off / targets / all; at most three individual alerts per round plus one summary; a name for the greeting.
- Ringing: looping alarm tone on the ALARM stream, repeating vibration, partial wake lock, full-screen alarm over the lock screen, Stop and Snooze 5 min, auto-stop after 3 min, alarm-stream volume raised to a 70% floor and restored afterwards. The Clock app is tried first (a 1-second timer, no UI) when allowed; the app's own alarm is the fallback so the phone always rings.
- Calendar: events sorted by time, impact 1–3, next-release countdown, reminder 10 min before (inexact while idle), Clock-app alarm only for releases within the next 24 h, "released" state, filter all or high impact, grouping by day, counter for simultaneous releases.
- Live monitor: foreground service of type specialUse with a Stop action, notification refreshed at most every 20 s, restarted after boot only when enabled.
- Default stars: bitcoin, ethereum, solana, ripple, usdt-irt.
- Everything that changes in defaults is in D-M08; nothing else is redesigned.


## K6 — Product integration

K6.1 Navigation (D-M07). Bottom bar, right to left: Today, Journal, Market, Calculator, More. Insights moves into More and into a top-bar action on Journal. Market is one destination with four sections in a scrollable segmented row: Prices, My coins, News, Alerts (labels in K13). Routes: market (opens on the last used section), market/prices, market/coins, market/news, market/alerts, market/coin/{id} (a bottom sheet). Route arguments are ids only; section and sheet survive process death. With the master switch off, Prices and My coins show the off state (mkt.off.*); News works fully because it is local. Build the bar from a list of destinations with a visible flag so the owner can change it in one place.

K6.2 Market header: USD/Toman toggle, refresh, the live-mode label, the data age. No language switch and no theme switch (Andarz Settings own them). The disclaimer (mkt.disclaimer) sits at the bottom of Prices.

K6.3 Defaults (D-M08). Market master switch off, no consent. Sharp-move alerts off. Background monitor off. Ring mode "notification only". Clock-app ring off. When the user turns alerts on: threshold 5%, window 15 min, scope watch-list, direction both, cooldown 30 min, include USDT/Toman on, name empty. Each special permission (exact alarms, full-screen intent, display over other apps) is requested only when the matching switch is turned on, through the system settings screen, with the one-line reason March already shows. POST_NOTIFICATIONS follows §7 (first time the user enables an alert, a reminder or the monitor).

K6.4 Hub demand (D-M22). The hub runs only while demanded and only when Market is enabled with consent. Reasons: (a) the Market screen is visible, which streams the full list; (b) the app is in the foreground and sharp-move alerts are enabled or a per-coin target is armed, which streams watch-list and rule coins only; (c) LiveService is running, same stream as (b); (d) in MK3, the trade-level watcher, which adds its symbols through extraSymbols. When no reason holds, no socket is open. March's acquire(ui)/release(ui) counting is the right shape.

K6.5 Alerts are information (D-M20). A price alert never touches the gate, locks, governor, journal or any parameter, and never writes to :data. Nothing in :market knows what a trade is.

K6.6 Notifications (D-M24, D-M18). Two channel groups: "discipline" (§7 channels) and "market" with price_alerts (high), price_alarm (high; silent channel because the tone is played on the alarm stream; bypass-DND flag as in March), live_monitor (low), releases (high). Names and descriptions come from content through MarketTexts; channels are created at app start. :market posts with the tag "market" so its ids cannot collide with the discipline reminders. Market notifications carry market data only; discipline notifications keep VISIBILITY_PRIVATE (§7). The alarm screen shows market data only. Quiet hours do not defer price alerts or release reminders: they are user-defined and time-critical (many US releases land at 21:30 Tehran time). P1: a switch "mute price alerts in quiet hours" (mkt.set.quiet) that posts them silently, default off.

K6.7 Voice (D-M15). No emoji anywhere in shipped strings: replace the flag emoji by the ISO country code in a small chip; replace the rocket, red-arrow, target, zap, check and clock emoji in notification titles by the arrows ▲ ▼ and plain words. No exclamation marks. No hype wording: the owner's constitution is about FOMO and law 8 forbids celebration. Up and down use the semantic tokens of §6.2 and are never shown by color alone: sign, arrow and color together.

K6.8 Watch-lists (D-M19). Two lists stay separate: Market's starred coins (March) and Andarz's discipline watch-list (§5.11, at most Watchlist_Max symbols, informational). No shared storage. MK3 adds display-only cross-links.

K6.9 Settings and About. Settings gets a "Market" section: master switch (mkt.set.enable), default USD/Toman display, link to Alerts, background monitor, the data-sources list (mkt.set.sources, built from the hosts constants), and in P1 the quiet-hours mute. About gets a network page (mkt.net.*) listing the hosts and what is sent, and the attribution line (mkt.about.credit). The threat model comment in code and About say that Market uses the internet.

K6.10 Calendar data (D-M16). The calendar is a static asset with a validUntil field; there is no network source. After validUntil, or when empty, News shows the expired state (mkt.cal.expired.*) and nothing else breaks. The list in March ends on 2026-10-29 (7 Aban 1405); after that date the shipped list is in the expired state. Say so in the README, document the JSON format and how the owner refreshes it. Do not add a fetch.

K6.11 Lock, alarm screen, deep links. The app lock covers the whole MainActivity, Market included. Tapping a market notification opens MainActivity, the lock screen first (§7), then the route (price alert → market/coin/{id}; release reminder → market/news; monitor → market). AlarmActivity lives outside the lock because it shows market data only.

K6.12 Backup. The encrypted backup carries market settings in MK3 (settings.market, §8.3). The consent flag and the master switch are excluded.


## K7 — Strings, theme, formatting

- Extraction (M0). Write tools/extract_march_strings.py (Python 3 is fine). It scans every .kt file of March for (a) tr("fa","en") calls and (b) any other line containing U+0600–U+06FF, and prints file, line, Persian, English and placeholders. You assign keys by hand (mkt.<area>.<name>), turn Kotlin templates ($x, ${x}) into {x}, and write app/src/main/assets/content_market_fa.json with the same shape as the spec file: "meta", "ui" (keys mkt.*), "uiArgs" (placeholder names per key), plus "overrides" (K13). Also write docs/march_strings_en.json (key → English, reference only, not packaged) so an English locale can be added later.
- Wording stays byte-identical to March except: (1) emoji removed; (2) the product name March, Bazaaryar, «مارچ» or «بازاریار» replaced by the app name, the value of the existing key app.name; (3) English dropped. Persian digits, ZWNJ and punctuation stay as they are. The keys of K13 take precedence; do not extract the same wording under a second key.
- Anything else missing goes to MISSING_COPY.md as in §0.3.
- ContentRepository loads content_fa.json and then content_market_fa.json. "overrides" replace values of the first file (a test checks that each override key exists there). A duplicate key between the two files fails a test. Every mkt.* key used in code must exist; unused keys are reported by a test (allow-list for dynamic keys).
- Law 3 scans every module and every test source. Persian may live only in JSON, in string resources generated from JSON (the manifest label) and in the calendar asset.
- Formatting. No android.icu and no String.format with the default locale. Prices, percentages and market caps go through MarketFmt on top of Fmt (§3.10), honoring the digit setting and the Jalali/zone settings; prices, symbols and hosts are isolated LTR runs (Appendix C trap 9). Keep March's tiers: price ≥ 1000 → 0 decimals, ≥ 1 → 2, ≥ 0.01 → 4, below that enough decimals for three significant digits (at most 10); market cap with T, B, M; percent with sign and arrow. Input parsing follows §3.10, not March's parseNum.
- Theme (D-M13). Andarz tokens only (§6). March's palette, Theme.kt, Motion.kt and Components.kt are not ported: rebuild the screens from Andarz components (SectionCard, StatTile, EmptyState, chips, sheets). Sparklines and coin charts use the Canvas helpers of §6.5, x axis left to right. Fonts: Vazirmatn vendored as in §2.2; no build-time download.
- Icons. Do not add material-icons-extended (§2.1). Use the core icon set where it has what you need and draw the few missing ones (bar chart, outlined star, active bell, alarm-add, event) as local vector drawables.

### K9.1 — MK3 in detail

(a) Backup. MarketPrefs.exportJson/importJson (validated, unknown fields ignored). :app embeds the result as settings.market in the payload of §8.3 and, after a restore, calls MarketModule.onRestored(): reschedule release reminders, restart the monitor only if it is enabled. Consent and the master switch stay off after a restore.
(b) Trade-linked price alerts. On an OPEN trade the user can arm one-shot notification alerts at the take-profit, at the partial-exit level of §5.4 (the price where floating R equals Partial_R_Lo) and at the stop. A watcher in :app combines the open trades with MarketRepository.state, so journal data never enters :market (D-M21). It posts Andarz notifications on the discipline channel with VISIBILITY_PRIVATE, using notif.partial.* for the partial level and mkt.link.notif.* for the others. It asks the hub for the needed symbols through extraSymbols and holds a foreground demand while an alert is armed. One-shot flags live in :data (a small schema addition with a migration test, recorded as a D-M entry) and vanish when the trade closes. The trade's symbol is resolved to a market coin by removing the suffixes USDT, USDC, USD, PERP and .P and matching the symbol exactly; if the match is not unique or the coin is not in the top 200, the card shows mkt.link.nocoin. If an engine helper for "price at R" is needed, add it to :engine with tests and record it; change no existing function. State in the UI that these alerts arrive only while the app is open or the monitor is on.
(c) Live price chip. In the wizard's entry-price field, in the calculator and in the trade's currentPrice field a chip shows the live price when Market is on and the quote is younger than 60 s (mkt.chip.*). Tapping it copies the number into the field as typed text. Nothing is stored as "from market".
(d) Watch-list rows (§5.11) show price and 24 h change when the symbol resolves, display only, only when Market is on.
(e) The quiet-hours mute switch (K6.6).
P2: a Toman equivalent line under equity on Today, display only, from a rate younger than 10 minutes and only if the user enables it.
